# S1.3.6 — Pre-Inference Admissibility Audit

**Status:** COMPLETE / PAID INFERENCE BLOCKED

## Purpose

S1.3.6 performs a deterministic audit before any paid model inference. It cross-checks the frozen calibration task sample against the currently verified canonical model registry, supported training-cutoff evidence, IF-01 exact-snapshot evidence, launch dates, and point-in-time input/output pricing.

The audit does not execute model APIs and does not change the frozen protocol.

## Frozen contamination interpretation

The protocol requires exclusion when a task release date precedes the training cutoff date of any model used in the test window. Current cutoff evidence is month-precision. S1.3.6 therefore uses a tri-state rule and does not invent an exact cutoff day:

- task release before the first day of the stated cutoff month -> `EXCLUDED`;
- task release after the last day of the stated cutoff month -> `ELIGIBLE`;
- task release inside the stated cutoff month -> `INDETERMINATE`.

This convention is conservative with respect to the evidence precision and is an implementation interpretation only; it does not modify the protocol.

## Current audit result

The frozen 10-task HumanEval calibration sample produces 30 task-year cells for 2024, 2025, and 2026. Against the four currently verified canonical snapshots:

- model-task-year pairs: **120**;
- admissible model-task-year pairs: **0**;
- task-year cells ready for paid inference: **0 / 30**;
- all 120 pairs are `CONTAMINATION_EXCLUDED`;
- paid inference gate: **BLOCKED**.

HumanEval was released on 2021-07-07 and MBPP on 2021-08-16. These dates precede all four currently supported cutoff months (2023-10, 2023-10, 2024-04, and 2024-07). Therefore all 164 HumanEval tasks and all 974 MBPP tasks are contamination-excluded against each of the four currently verified snapshots.

## K4 implication — risk signal, not final decision

K4 is frozen as: more than 30% of tasks in the dataset flagged for contamination/exclusion.

The current static benchmark registry contains 1,138 HumanEval + MBPP tasks, all of which fail the contamination gate against the currently verified snapshots. This is a severe pre-inference K4 risk signal, but S1.3.6 does **not** mark K4 as formally triggered because:

1. the timestamp-filtered LeetCode Weekly Contest Hard task universe has not yet been frozen;
2. the final model registry is not yet complete;
3. the denominator and final task-universe interpretation must be determined from the frozen protocol and completed task registry, not inferred post hoc.

If the final dataset denominator includes these 1,138 excluded static tasks, at least **2,656 additional non-excluded tasks** would be required for their exclusion share alone to be at or below 30%. This is a mathematical threshold, not a forecast that such a LeetCode set exists.

## Important protocol-design consequence

This audit exposes a structural tension in the frozen protocol: HumanEval and MBPP are explicitly named as Easy/Medium task sources, while the mandatory contamination rule excludes tasks released before model training cutoffs. For modern 2024–2026 models with verified post-2021 cutoff dates, the static HumanEval/MBPP task sets cannot contribute confirmatory observations under that rule.

This finding must **not** be repaired by changing the contamination threshold, changing benchmark release dates, substituting successor models, or retroactively weakening K4. The protocol is frozen. The correct next action is to complete the timestamp-filtered LeetCode Hard task universe and quantify the registered K4 denominator before authorizing paid inference.
