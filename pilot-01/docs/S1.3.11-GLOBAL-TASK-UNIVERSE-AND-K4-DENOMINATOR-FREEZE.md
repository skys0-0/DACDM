## 4. Rejected denominator interpretations

| Interpretation | Decision | Reason |
|---|---|---|
| Only post-contamination survivors | Rejected | It removes the excluded tasks from the denominator used to measure their exclusion share, making K4 partly self-erasing. |
| Only S1.3.10 IF-09-ready tasks | Rejected | It conditions K4 on a later oracle gate and omits tasks that contamination already removed. |
| Only tasks with observed model results | Rejected | It would define the denominator after inference outcomes, contrary to the pre-inference gate and no-post-hoc-reinterpretation rule. |

This decision is based on protocol coherence, not on whether it makes K4 easier or harder to pass.

## 5. Global contamination semantics

K4 contamination is frozen as **global task-level contamination**:

- evaluate the task against every model in the frozen test-window model set;
- if any such model excludes the task under the Protocol contamination policy, the task is globally `EXCLUDED`;
- if no model excludes it but at least one result is unresolved because of cutoff precision, the task is `INDETERMINATE`;
- otherwise the task is `ELIGIBLE`.

For month-precision cutoffs, S1.3.6 precision preservation remains in force: releases before the first day of the cutoff month are excluded, releases after the last day are eligible, and releases within that month are indeterminate. Unknown cutoffs use the Protocol's exact six-calendar-month fallback.

`INDETERMINATE` is reported separately and is not silently counted as excluded in the primary K4 numerator. A conservative upper-bound sensitivity may count it as excluded, but that cannot replace the registered primary calculation.

## 6. Test-window model-set boundary

The Protocol refers to models **used in the test window**, not every model that happens to have evidence in the repository.

S1.3.11 therefore operationalizes final test-window membership using the existing machine-readable flag:

`models.json: enabled_for_pilot = true`

At the S1.3.11 freeze, all four currently evidence-populated models remain `enabled_for_pilot: false`. They are evidence candidates, not yet the final frozen test-window model set. Consequently, S1.3.11 does **not** convert their contamination results into the formal K4 decision.

The formal status at this gate is therefore:

`K4_UNRESOLVED_MODEL_SET`

Paid inference remains blocked.

## 7. Current evidence-registry sensitivity

Although the four current models are not yet the formal test-window set, applying the frozen global rule to them provides a pre-outcome sensitivity check:

- denominator: 1,301 tasks;
- `EXCLUDED`: 1,165;
- `INDETERMINATE`: 4;
- `ELIGIBLE`: 132;
- exclusion fraction: `1165 / 1301 = 0.8954650269` (89.55%);
- conservative fraction if the four indeterminate tasks were also excluded: `1169 / 1301 = 0.8985395849` (89.85%);
- K4 threshold: 30%.

Under this **sensitivity-only** model set, K4 would trigger.

The HumanEval + MBPP block alone contributes 1,138 contamination exclusions under all four current evidence models. Even if every one of the 163 LeetCode Hard candidates were treated as clean, the exclusion fraction would be:

`1138 / 1301 = 0.8747117602` (87.47%).

This is a strong structural warning, but it is not labeled the formal K4 result because the Protocol's final test-window model set has not yet been frozen.

## 8. Why S1.3.11 does not terminate Pilot 01 yet

A formal termination now would silently equate "models with evidence in `models.json`" with "models used in the test window." That equivalence is not yet true: all four entries are explicitly disabled for Pilot execution, and the broader tier/model population remains incomplete.

The correct research-integrity action is therefore to freeze the denominator now, keep the unfavorable sensitivity visible, and resolve the model-set membership before making the final numeric K4 decision.

The denominator is no longer available as a degree of freedom for rescuing the Pilot later.
