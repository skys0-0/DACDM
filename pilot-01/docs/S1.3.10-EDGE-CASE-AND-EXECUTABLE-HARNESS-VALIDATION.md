## 1. Objective

S1.3.10 validates the 45 numerically sufficient external LeetCode oracle suites registered in S1.3.9 against the two IF-09 requirements that were still open:

1. reproducible evidence of ordinary and boundary/edge cases; and
2. deterministic execution of the frozen reference solution against the frozen registered test harness.

A task is marked `IF09_ORACLE_READY` only when all of the following are true:

- at least 20 distinct registered tests are already present from S1.3.9;
- at least one registered case is supported as an ordinary case by a documented constraint;
- at least one registered case hits an exact documented lower or upper constraint bound and therefore provides boundary/edge evidence;
- the frozen reference program passes the source test harness in two independent sandbox executions.

No task-level success in this phase opens the global paid-inference gate.

## 2. Edge-evidence rule

S1.3.10 does not label a case as an edge case because it merely looks unusual, is the largest observed test, or has an extreme value relative to the generated suite.

The validator parses documented problem constraints from the frozen problem description. Supported forms include scalar bounds, collection-length bounds, indexed element bounds, and nested collection-length bounds. HTML superscript notation is normalized before parsing.

For a parsed bound such as:

```text
1 <= nums.length <= 100000
```

an observed registered case is treated as:

- **boundary/edge evidence** only when the relevant quantity is exactly `1` or `100000`;
- **ordinary evidence** when the relevant quantity is strictly between the documented bounds.

If the validator cannot map a documented bound to the serialized input, it does not invent coverage. The task remains insufficient on that dimension.

