# S1.3.3 — Training Cutoff Evidence

Status: IMPLEMENTED / CI PENDING

## Purpose

This gate records model training or knowledge cutoffs without inventing precision that the first-party source does not provide. It is part of the contamination-control foundation for DACDM Pilot 01.

## Precision rule

Training cutoff evidence is represented as one of:

- `day`: an exact calendar date is explicitly supported by the source;
- `month`: only a year-month is supported;
- `unknown`: no usable cutoff value is supported.

A month-level source MUST NOT be converted into an assumed first day, last day, midpoint, or other synthetic exact date. The registry therefore stores `claimed_cutoff_month` separately from `claimed_cutoff_date`.

All four records are marked `supported` with high confidence. No exact cutoff day is inferred for the contamination engine.

## Registry reconciliation

A canonical model with `training_cutoff_status = supported` must reference at least one `TrainingCutoffEvidenceRecord` for the same model whose evidence status is `supported`. A model marked `conflicting` must reference conflicting evidence. An `unknown` model must not carry affirmative cutoff evidence references.

## Contamination-engine boundary

S1.3.3 records evidence only. It does not silently choose a day-level interpretation for month-precision cutoffs. The contamination engine must consume the precision explicitly and apply a separately documented deterministic boundary rule before confirmatory task eligibility is computed.

The frozen protocol's six-month fallback remains reserved for genuinely unknown training cutoffs; a known month is not rewritten as unknown merely because the exact day is unavailable.

## Research-integrity consequences

- Provider documentation outranks third-party summaries for the primary registry.
- Exact model identity and cutoff evidence remain separate claims.
- Model snapshot suffixes are not treated as training-cutoff evidence.
- Missing precision remains missing precision.
- No post-hoc contamination rule may be selected based on observed benchmark outcomes.
