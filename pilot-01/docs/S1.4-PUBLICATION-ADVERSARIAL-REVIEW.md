## 1. Review verdict

**MAJOR REVISIONS REQUIRED BEFORE ZENODO PUBLICATION.**

The frozen S1.3.13 package is unusually transparent about the K4 trigger and correctly avoids claiming that H2/H4 received a model-performance test. The numerical K4 calculation is internally consistent with the S1.3.11 denominator interpretation and S1.3.12 anchor model set. However, the current publication narrative still risks overstating how much of the decisive operationalization was literally preregistered on 2026-08-14.

The package should not be published unchanged. The required corrections below are wording/provenance corrections, not attempts to rescue Pilot 01 or change the 30% threshold.

## 2. Major issue P1 — K4 denominator semantics were operationalized after preregistration

The frozen protocol states that K4 is triggered when more than 30% of tasks in the dataset are flagged for contamination and excluded. It does **not** explicitly define whether the K4 denominator is the pre-contamination registered universe, post-contamination survivors, post-oracle survivors, or another frame.

S1.3.11 resolved that ambiguity as:

`PRE_CONTAMINATION_REGISTERED_TASK_UNIVERSE`

This is a defensible interpretation because using post-contamination survivors would make the contamination-exclusion share partly self-erasing. It was also frozen before the formal S1.3.12 K4 decision. Nevertheless, it is an **implementation interpretation made after the protocol freeze**, not a literal denominator definition written in the original preregistration.

### Required publication correction

The final report must explicitly distinguish:

- **preregistered:** K4 threshold = 30%, contamination policy, ANY-model exclusion wording, kill-criterion status;
- **post-preregistration but pre-inference operationalization:** K4 denominator semantics frozen in S1.3.11.

Avoid phrases that could imply the denominator semantics themselves were preregistered. Recommended wording:

> “The preregistered protocol specified the K4 threshold and contamination rule but left the K4 denominator operationally ambiguous. Before confirmatory inference and before the final K4 decision, S1.3.11 froze the denominator as the pre-contamination registered task universe.”

## 3. Major issue P2 — Test-window anchor model set was not preregistered

The original protocol lists representative models by tier but does not freeze the exact model membership used for K4. S1.3.12 later selected:

`ALL_CANONICAL_MODELS_PRESENT_BEFORE_S1_3_12`

This rule is reproducible and does not use model-performance outcomes. However, the S1.3.11 sensitivity analysis had already shown that the then-current four-model registry would exceed K4. Therefore the publication must not imply that the exact four-model anchor set was preregistered or selected before any knowledge of K4 sensitivity.

The monotonicity argument remains important: under the frozen ANY-model rule, adding models cannot reverse an exclusion already caused by a selected model. But that only establishes a lower-bound property **conditional on the selected anchor models legitimately belonging to the test window**.

### Required publication correction

State clearly that:

1. the exact anchor set was frozen in S1.3.12, not in the original protocol;
2. it was selected before paid/model-performance inference, but after pre-inference contamination sensitivity was known;
3. the formal K4 result is therefore an application of the frozen protocol **plus the S1.3.11/S1.3.12 pre-inference operationalizations**.

Do not describe the four models as though the original preregistration had explicitly named them as the final test-window set.

## 4. Major issue P3 — “Falsification” must be framed as protocol terminology, not substantive evidence

The protocol literally says the pilot is considered a falsification if any kill criterion is observed, including K4. The S1.3.13 report already states that H2/H4 were not model-performance tested. This is scientifically essential.

For external publication, however, the phrase “falsification of DACDM” can easily be misread as evidence against Complexity Migration or Compression Beyond Hardware. K4 is primarily a benchmark-admissibility/design termination condition.

### Required publication correction

Use **“pre-inference termination under the preregistered K4 criterion”** as the primary description in the title, abstract, Zenodo description, keywords, and README.

When “falsification” is used, qualify it as:

> “the protocol mechanically classifies K4 as a falsification condition”

and immediately state that this is not a model-performance refutation of H2/H4.

Recommended Zenodo classification: **methodological termination report / preregistered design result**, rather than leading with “negative result.”

## 5. Major issue P4 — Protocol Data Dictionary sign conflict must remain visible

The mandatory contamination policy excludes tasks whose release date precedes a model training cutoff. The Data Dictionary contains the opposite short description for `exclude_contamination`.

The S1.3.13 report appropriately discloses this defect and follows the mandatory policy under the documented authority hierarchy. This is acceptable only if the final publication preserves the defect verbatim as a limitation and does not present the protocol as internally contradiction-free.

### Required publication correction

Keep a dedicated limitations paragraph stating that:

- the frozen protocol contains an internal sign inconsistency;
- the implementation followed the main mandatory policy based on the documented authority hierarchy;
- no post-hoc change to the 30% threshold occurred;
- an independent reader can reproduce the alternative interpretation and see that it would represent a different rule, not the implemented preregistration hierarchy.
