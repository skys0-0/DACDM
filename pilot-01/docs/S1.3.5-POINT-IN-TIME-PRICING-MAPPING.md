# S1.3.5 — Point-in-Time Pricing Mapping

Status: IMPLEMENTED / CI PENDING

## Purpose

Map historical token prices only to canonical, first-party-verified model snapshots. A family or rolling alias price must not be silently inherited by a dated historical snapshot.

## Rules

1. Every canonical pricing record is attached to exactly one canonical `model_id`.
2. Input and output prices are represented as separate records.
3. `effective_from` / `effective_to` define a half-open applicability interval `[from, to)`.
4. Price intervals for the same model and variation must not overlap.
5. A model with pricing evidence must reference both input and output evidence.
6. Provider and model ownership must reconcile across `models.json` and `pricing.json`.
7. Later family-alias repricing does not mutate an older immutable snapshot price unless first-party evidence explicitly states that the old snapshot's billing rate changed.
8. Archived first-party evidence is acceptable when the live provider page no longer exposes the historical price.
9. The frozen AI Price Index snapshot remains supporting provenance; it does not independently establish canonical model identity.

## Initial mapped snapshots

- `openai:gpt-4o-2024-05-13`: $5 / 1M input, $15 / 1M output. The later 2024-08-06 GPT-4o snapshot price reduction is not back-propagated to the May snapshot.
- `openai:gpt-4o-mini-2024-07-18`: $0.15 / 1M input, $0.60 / 1M output.
- `anthropic:claude-3-5-sonnet-20240620`: $3 / 1M input, $15 / 1M output until API retirement.
- `anthropic:claude-3-5-haiku-20241022`: launch pricing $1 / $5, followed by the documented 2024-12-03 reduction to $0.80 / $4 until API retirement.

## Research-integrity consequence

The micro-backtest may query a price only when an observation date falls inside a canonical price interval for an admissible model snapshot. Missing intervals remain unavailable rather than being filled from successor models or current aliases.
